Profile

VR・AR・MRの開発に携わって8年。新しいデバイスや機能をいち早く検証し、設計・実装し、現場で使われ続けるところまで持っていくことを仕事にしています。

キャリアの始まりは飲料メーカーの営業職です。技術への憧れからVRエンジニアに転身しました。その後、VR安全教育の受託開発、XRのR&D、XRプラットフォームSTYLYの開発を経て、2023年に独立。2024年には株式会社UDを設立し、ARグラスのコンテンツや新規事業の開発をリードしています。

担ってきたのは、技術検証、設計、実装、チームリード、プロジェクト推進。少人数のチームで開発することが多く、役割を限定せずにその時プロジェクトに足りないものを自分で埋めてきました。企画から運用までを一通り自分の手で回せることが強みです。

Values

何を作ったか以上に、どう考えて作るか。仕事で意識している6つのことと、その根拠です。

まず触って、判断材料にする。

新しいデバイスやSDKは、資料を読むより先に手を動かします。ただし目的は動かすことではなく、「どの条件なら使えるか・何がリスクか」を言語化して、チームや顧客が決められる状態にすることです。

アップフロンティアでXRのR&Dを担当し、Immersal・LiDAR・Magic Leap・PLATEAU・VPSなどの検証結果を社外に公開。STYLYでは技術検証チームのテックリードとして、新機能の検証からプロダクトへの組み込みまでを担当。独立後は「こういうものを作りたい」というアイデアだけを受け取ることも多く、実現方法の調査・技術選定から、顧客とのすり合わせ、設計・実装までを自分で組み立てている。

体験から逆算する。

XRは「技術的にできる」と「体験として成立する」の差が大きい分野です。だから最初に、誰が・どこで・どう使えば価値が出るかの仮説とゴールを置き、そこから逆算して進めます。

序盤は、その道筋に関係のなさそうな検証には手を広げません。まず最小限のものを作って仮説が有効かを確かめ、結果を見ながら調整していく。この順番が最も効率的だというのが、経験から得た実感です。

VR安全教育では事故事例の調査や顧客取材から企画に参加。医療系ARでは技術コンサルティングとして要件定義から入り、現場の制約を前提に設計。

変化に耐える設計にする。

XRはデバイスもSDKも入れ替わりが激しい。だからプラットフォームの差分は一箇所に閉じ込め、機能追加や移植で壊れない構造を優先します。役割ごとに責務を分け、後から入った人でも読めて直せるコードであることを重視しています。

STYLYでは、VR・AR・モバイル・Webなど多数のプラットフォームに同時対応するプロダクトの機能開発とコードレビューを担当し、その仕組みを CA.Unity で登壇。その経験を活かし、独立後の新規開発でも、設計からリリース、運用・保守まで一気通貫で実施。

知見は言語化して、資産にする。

技術記事を書き続けて身についたのは、理解したことを言語化し、他の人が再現できる形で残す習慣です。今その出力先は、公開記事からチームのドキュメントや、AIエージェントが参照するルール・手順書へと移っています。書いた知見が、人にもAIにも使われ続けることを意識しています。

Qiita 197本・Zenn 95本（シェーダー中心）の技術記事と、CA.Unity などでの登壇。現在はプロジェクトごとにコーディングエージェント向けのルールや自動チェックを整備し、チームの判断基準をAIにも共有している。

AIと組んで、少人数で速く作る。

Claude Code や Codex を日常的に使い、Unity・Webを問わず開発の中心に組み込んでいます。AIと組むことで、得意領域の外にも踏み込んで、動くものを速く形にできるようになりました。AIに任せる領域と人が判断すべき領域を切り分けて、少人数でも速度と品質を両立させることを意識しています。

2025年以降の案件で Claude Code・Codex を活用し、Unity では Editor をエージェントから操作する uloop も導入。最新の案件ではWebの領域にも手を広げ、設計からリリースまで責任者として開発を担当。

技術を、事業に繋げる。

良いデモを作ることと、それが事業になることは別物です。プロトタイプを協業や商談に繋げる、アイデアを続けられる形に育てる。その「次の一歩」まで考えて動きます。

enXross HACKATHON（258名・93チーム）での最優秀賞を機に株式会社東京ドームと協業し、ARグラスの次世代アーケードゲームを開発。上場企業グループ会社の新規事業開発にも技術検証・要件定義から参画。
